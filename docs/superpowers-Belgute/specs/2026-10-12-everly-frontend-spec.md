# Everly: Frontend spec (mock өгөгдөлтэй)

Огноо: 2026-10-12 · Төлөв: Хянахыг хүлээж байна
Холбоотой: `2026-10-12-everly-grocery-design.md` (бүх системийн spec), `../plans/2026-10-12-everly-frontend.md` (хэрэгжүүлэх plan)

## 1. Зорилго

Everly хүнсний онлайн дэлгүүрийн React frontend-ийг backend-гүйгээр, mock өгөгдөл дээр бүрэн ажиллагаатай болгох. Хэрэглэгч бараа үзэж, сагслаж, нэвтэрч, захиалж, (mock) төлж, түүхээ харна. Админ бараа, нөөц, захиалгын төлөв харна.

**Ялалтын шалгуур:** нэвтрээгүй зочин нүүрнээс эхлээд захиалгаа баталгаажуулж, хуудсыг refresh хийсний дараа ч захиалгаа харна. Бүгд 390px өргөнтэй утсан дээр хэвтээ scroll-гүй ажиллана.

## 2. Технологи

Next.js (React 19, App Router), TypeScript, Tailwind CSS. Тест: Vitest + Testing Library, Playwright. Өгөгдлийн давхарга: `src/data/api.ts` дахь `Api` интерфейс (одоо mock + `localStorage`, дараа нь HTTP-ээр солино).

## 3. Хүрээ

**Багтана:** каталог, хайлт, бүтээгдэхүүний хуудас, сагс, mock OTP нэвтрэлт, checkout, mock QPay ба бэлнээр төлөх, захиалгын түүх ба дахин захиалах, админ харагдац (бараа, нөөц, захиалгын төлөв).

**Багтахгүй:** бодит backend/DB, бодит SMS ба QPay, админы нэвтрэлт, газрын зургийн pin, SMS мэдэгдэл, тогтмол захиалга, купон/оноо, жор, англи хэл.

## 4. Дэлгэцүүд

| Зам | Агуулга | Нэвтрэлт |
|---|---|---|
| `/` | Ангиллын чип, ангилал бүрийн эхний 4 бараа | Үгүй |
| `/c/[slug]` | Ангилалын барааны жагсаалт | Үгүй |
| `/search?q=` | Хайлтын үр дүн; үр дүнгүй бол санал болгох ангиллууд | Үгүй |
| `/p/[slug]` | Нэр, үнэ/нэгж, тайлбар, гарал үүсэл, хадгалах хугацаа, сагсанд нэмэх | Үгүй |
| `/cart` | Мөр бүрийн тоо хэмжээ засах/устгах, нийт дүн | Үгүй |
| `/login` | Утас → OTP код | Үгүй |
| `/checkout` | Хаяг, бүс, цонх, орлуулалт, төлбөрийн арга, хураангуй | Шаардана |
| `/pay/[orderId]` | Mock QPay (QR placeholder + "Төлсөн гэж тэмдэглэх") | Шаардана |
| `/orders`, `/orders/[id]` | Түүх, дэлгэрэнгүй, дахин захиалах | Шаардана |
| `/admin`, `/admin/products`, `/admin/orders` | Тойм, нөөц засах, төлөв ахиулах | Үгүй (туршилт) |

Нэвтрээгүй хэрэглэгч хамгаалагдсан зам руу орвол `/login?next=<зам>` руу чиглэнэ. `next` нь зөвхөн `/`-ээр эхэлсэн дотоод зам байх ёстой (`//` ба `http…` үл зөвшөөрнө).

## 5. Гол урсгал ба дүрмүүд

**Сагс**
- Тоо хэмжээ бүхэл, `0 ≤ qty ≤ stock`. Нөөц дууссан бараа сагсанд орохгүй, карт дээр "Дууссан". Нөөц 3-аас бага бол "Цөөхөн үлдсэн".
- Сагс зөвхөн `productId` ба `qty` хадгална; үнийг үргэлж одоогийн каталогоос тооцно.
- `/cart` ачаалахад сагсыг нөөцтэй тулгана: нөөцөөс их тоог бууруулж, дууссан барааг хасаад "Зарим барааны тоо нөөцөд тааруулж өөрчлөгдлөө" гэж мэдэгдэнэ.

**Нэвтрэлт (mock)**
- Утас 8 орон, `[6789]`-өөр эхэлнэ (`+976` зөвшөөрнө). Код үргэлж `123456`, UI-д "Туршилтын код: 123456" гэж харуулна.
- Код 5 минутын дараа хүчингүй; 5 буруу оролдлогын дараа түгжинэ; дахин илгээх 60 секундэд нэг удаа.

**Checkout**
- Хаяг (заавал), хүргэлтийн бүс, цонх (зөвхөн дүүрээгүй), "Бараа дууссан үед орлуулж болно" (нэг удаагийн сонголт), төлбөрийн арга (QPay эсвэл бэлнээр).
- Бүс сольбол өмнө сонгосон цонх цэвэрлэгдэнэ.
- "Баталгаажуулах" товч доорх тохиолдолд идэвхгүй бөгөөд шалтгааныг текстээр харуулна: хаяггүй, бүс/цонхгүй, цонх дүүрсэн, дүн доод хэмжээнээс бага, илгээж байна.
- Давхар товшилтоор давхар захиалга үүсэхгүй.
- Алдаа: `OUT_OF_STOCK` → "Зарим бараа дууссан, сагсаа шалгана уу" (сагс автоматаар засагдана), `SLOT_FULL` → "Энэ цонх дүүрсэн, өөр цаг сонгоно уу", `BELOW_MINIMUM` → "Хамгийн бага захиалгын дүн {n}".

**Төлбөр (mock)**
- Бэлнээр: захиалга шууд `Баталгаажсан`.
- QPay: `Төлбөр хүлээж буй` төлвөөр `/pay/[id]` руу; "Төлсөн гэж тэмдэглэх (туршилт)" товч `Баталгаажсан` болгоно. Давхар дарахад аюулгүй. Аль хэдийн төлөгдсөн бол шууд захиалгын хуудас руу.

**Захиалга**
- Төлөв: Төлбөр хүлээж буй → Баталгаажсан → Бэлтгэж байна → Хүргэлтэнд гарсан → Хүргэгдсэн; мөн Цуцлагдсан.
- Мөр нь захиалгын үеийн нэр, үнийг хуулж хадгална. Хэрэглэгч зөвхөн өөрийн захиалгыг харна.
- "Дахин захиалах": өмнөх мөрүүдийг сагсанд нэмнэ; нөөц хүрэхгүй бол байгаагаар нь, дууссаныг орхиж мэдэгдэнэ.

**Админ (mock)**
- Нөөц: `0` ба түүнээс их бүхэл тоо. Буруу утга өөрчлөгдөхгүй, алдаа харагдана.
- Захиалгын төлөв зөвхөн дараагийн зөвшөөрөгдсөн төлөв рүү; `Хүргэгдсэн`/`Цуцлагдсан` дээр товчгүй.
- "Нэвтрэлтгүй туршилтын харагдац" баннертай.

## 6. Mock өгөгдөл

- 6 ангилал (id нь slug-тай ижил), 24+ бараа (мах, ногоо `KG`-аар; нэг нь `stock = 0`, нэг нь `stock = 2`), үнэ бүхэл ₮, бараа бүр `vendorId: "everly"`.
- 3 бүс: БЗД (хураамж 3,000₮, доод дүн 20,000₮), СХД (3,500₮, 25,000₮), ХУД (4,000₮, 30,000₮).
- Цонх: өнөөдөр, маргааш, нөгөөдөр 10–12, 12–14, 16–18, 18–20, capacity 6; зарим нь дүүрсэн; өнгөрсөн цонх харагдахгүй. Цонхны id тодорхой (`${zoneId}-${YYYYMMDD}-${HH}`).
- Төлөв `localStorage`-д (`everly.cart`, `everly.session`, `everly.orders`, `everly.stock`, `everly.slotBooked`, `everly.otp`, `everly.version`). Хувилбар зөрвөл бүгдийг цэвэрлэнэ. `localStorage` хаалттай эсвэл эвдэрсэн бол аппликейшн унахгүй, хоосон төлвөөр эхэлнэ.
- Бүх UI-д "Туршилтын горим: бодит төлбөр, хүргэлт байхгүй" баннер, мөн "Mock өгөгдөл сэргээх" товч.

## 7. UI ба хүртээмж

- Бүх текст монгол кирилл; мөнгө `12,500₮` (таслалтай, бүхэл).
- Mobile-first; 390px-д хэвтээ scroll байхгүй.
- Зураггүй: ангиллын эможи өнгөт дэвсгэр дээр placeholder.
- Өгөгдөл ачаалах үед skeleton, хоосон/алдааны төлөв бүрийн тусгай текст.
- Input бүр `<label>`-тай, товч бүр харагдах текст эсвэл `aria-label`-тай, фокус харагдана.

## 8. Backend-д шилжих

UI нь зөвхөн `Api` интерфейсээр өгөгдөл авна. Backend бэлэн болоход `src/data/api.ts`-ийг HTTP хэрэгжилтээр солино; mock ба HTTP хоёр нэг contract тестийг давна (`../plans/2026-10-12-everly-mvp-fullstack.md` Task 11).

## 9. Нээлттэй асуулт

- Брэндийн өнгө, лого, фонт (одоо Tailwind-ийн саарал суурь өнгө ашиглана).
- Бүтээгдэхүүний бодит зураг хэзээ, хаанаас ирэх.
- Админ харагдацыг эцсийн хувилбарт нэвтрэлттэй болгох (backend-ийн үед).
