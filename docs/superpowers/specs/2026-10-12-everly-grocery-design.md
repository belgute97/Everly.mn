# Everly: хүнсний онлайн дэлгүүр. Дизайн spec (MVP)

Огноо: 2026-10-12 · Төлөв: Хянахыг хүлээж байна

## 1. Зорилго ба хүрээ

Everly нь Улаанбаатарын цөөн бүсэд хүнс (онцгойлон шинэхэн бүтээгдэхүүн) гэрт нь хүргэдэг онлайн дэлгүүр.

**Баталгаажсан (хэрэглэгчийн хэлсэн):**
- Эхний ээлжинд хүнс.
- Frontend нь React.
- Бараагаа өөрөө нөөцөлж, өөрөө хүргэнэ (marketplace биш). Хэрэглэгч өөрөө шийдээгүй гэсэн ч өөрийн агуулах + хүргэлтээр эхлэхийг зөвшөөрсөн.
- Эхний хүргэлтийн хүрээ: Улаанбаатарын цөөн дүүрэг/бүс.
- Хөгжүүлэлтийг голдуу Claude хийнэ, хэрэглэгч чиглүүлнэ.

**Таамаг (хянах шаардлагатай):**
- Хэл: монгол (кирилл). Англи хэл MVP-д орохгүй.
- Валют: ₮ (MNT).
- Өөрийн жолооч, машин ашиглана.
- Нэг агуулах, нэг худалдагч (Everly өөрөө).

**Ялалтын шалгуур:** шинэ хэрэглэгч утасны дугаараар нэвтэрч, бараа сонгон QPay-аар төлж, сонгосон цагийн цонхонд хүргүүлж чадна. Ажилтан админ самбараас захиалгыг боловсруулж хүргэлтэд гаргана.

## 2. Хүрээнээс гадуур (MVP-д байхгүй)

Тогтмол захиалга, купон/оноо/гишүүнчлэл, жор, жолоочийн апп ба бодит цагийн хяналт, хувийн санал болгох систем, олон худалдагч, аймаг руу хүргэх, англи хэл.

## 3. Технологийн сонголт

| Давхарга | Сонголт | Шалтгаан |
|---|---|---|
| Framework | Next.js (React) + TypeScript | React шаардлага, SEO (бүтээгдэхүүний хуудас Google-д орох) |
| Стиль | Tailwind CSS | Хурдан, mobile-first |
| Өгөгдлийн сан | PostgreSQL + Prisma | Захиалга, нөөц зэрэг холбоост өгөгдөлд тохиромжтой |
| Хайлт | PostgreSQL full-text + trigram (`pg_trgm`) | Үсгийн алдааг зөвшөөрнө, нэмэлт үйлчилгээ шаардахгүй |
| Нэвтрэлт | Утасны дугаар + SMS OTP | Монголд нийтлэг, нууц үг шаардахгүй |
| Төлбөр | QPay (эхлээд), дараа нь SocialPay, Pocket | QPay нь зах зээлд давамгайлдаг |
| Хадгалалт | Бүтээгдэхүүний зургийг object storage-д | |
| Архитектур | Нэг Next.js аппликейшн (monolith), storefront + admin + API | Нэг хүнд/багт дэмжихэд хялбар |

SMS provider болон hosting-ийг plan дээр сонгоно. Хоёулаа Монголын операторын SMS хүргэлт, хаягийн бодит байдлаас хамаарна.

## 4. Module ба үүрэг

1. **Каталог:** ангилал, бүтээгдэхүүний хуудас (зураг, нэгж үнэ, жин/ширхэг, гарал үүсэл, хадгалах хугацаа, найрлага). Бараа бүр `vendor_id` талбартай (одоо бүгд Everly) гэсэн нь дараа нь marketplace болгох замыг хаахгүй.
2. **Хайлт:** нэр, ангилалаар. Үсгийн алдаа, кирилл/латин хоёуланг дэмжинэ.
3. **Сагс:** нэр, тоо хэмжээ, нийт дүн. Нэвтрээгүй байхад ч хадгалагдаж, нэвтэрсний дараа нэгдэнэ.
4. **Checkout:** хаяг (газрын зургийн pin + тайлбар хаяг), хүргэлтийн цонх, орлуулалтын сонголт, төлбөр.
5. **Хүргэлтийн бүс ба цонх:** бүсээр хураамж, хамгийн бага захиалгын дүн, цонх бүрт авах захиалгын хязгаар (capacity).
6. **Орлуулалт:** захиалгын түвшинд нэг сонголт ("орлуулж болно" / "болохгүй"). Бараа дууссан үед ажилтан орлуулж, хэрэглэгчид мэдэгдэнэ.
7. **Төлбөр:** QPay invoice үүсгээд callback-ээр баталгаажуулна. Бэлнээр төлөх сонголт нь хүргэлт дээр.
8. **Бүртгэл:** OTP нэвтрэлт, хаягийн дэвтэр, захиалгын түүх, "дахин захиалах" товч.
9. **Захиалгын төлөв:** шинэ → баталгаажсан → цуглуулж байна → хүргэлтэд гарсан → хүргэгдсэн / цуцлагдсан. Төлөв өөрчлөгдөхөд SMS.
10. **Админ самбар:** бараа, үнэ, нөөц, захиалга, хүргэлтийн бүс ба цонх, ажилтны эрх (admin / ажилтан).

## 5. Өгөгдлийн үндсэн загвар (өндөр түвшин)

`User`, `Address`, `Category`, `Product` (vendor_id, unit, price, stock), `Cart`/`CartItem`, `Order`/`OrderItem` (захиалгын үеийн үнийг хуулж хадгална), `DeliveryZone`, `DeliverySlot`, `Payment`, `StaffUser`.

Жингээр зарагддаг бараа (мах, хүнсний ногоо) MVP-д ойролцоо жингээр захиалагдаж, эцсийн үнийг ажилтан жинлэснээр засна. Энэ нь админы гараар хийх алхам.

## 6. Алдааны зохицуулалт

- **QPay callback ирэхгүй бол:** захиалга "төлбөр хүлээж буй" төлөвт үлдэж, давтан шалгана. Хугацаа хэтэрвэл цуцлана.
- **Нөөц дууссан:** сагсанд нэмэх, checkout хийх үед шалгана. Давхар захиалгаас сэргийлэхийн тулд нөөцийг transaction дотор хасна.
- **Цонх дүүрсэн:** сонгох үед шалгаж, дүүрсэн цонхыг идэвхгүй болгоно.
- **SMS хүрээгүй:** OTP-г дахин илгээх хязгаартай товч, захиалгын мэдэгдлийг админаас дахин илгээж болно.

## 7. Тест

- Нэгжийн тест: үнэ/хураамжийн тооцоо, нөөцийн хасалт, цонхны capacity, захиалгын төлөвийн шилжилт.
- Интеграцийн тест: QPay sandbox-оор төлбөрийн урсгал, OTP нэвтрэлт.
- End-to-end: бараа сонгох → checkout → төлбөр → админ боловсруулах гол замыг Playwright-аар.

## 8. Эрсдэл ба нээлттэй асуулт

- QPay merchant бүртгэл, sandbox эрх олж авах хугацаа. Төслийн хамгийн их хугацаа авах хэсэг байж болно.
- Хаягийн чанар: газрын зургийн provider (Google Maps эсвэл OpenStreetMap) сонгох.
- Хүйтэн сүлжээ (шинэхэн мах, сүү) хүргэлтэд ямар шаардлага тавих вэ.
- Анхны барааны каталогийг хэн, ямар форматаар оруулах (CSV импорт хэрэгтэй эсэх).
- Нээх хугацаа, төсөв тодорхойгүй.
